# ชุดทดสอบสลิป (test set)

> **สลิปจริงอยู่ในเครื่องเท่านั้น**: `data/raw/` กับ `data/labels.jsonl` ถูก `.gitignore` ไว้
> สิ่งที่ commit ได้คือ `labels.example.jsonl` (ข้อมูลปลอม) และผลสรุปใน `results/`

## เป้าหมายรอบแรก
- 3 ธนาคาร: **KBank, SCB, Krungthai** (ฐานผู้ใช้ mobile banking ใหญ่สุด) ธนาคารละ **~30 ใบ** รวม ~90 ใบ
- ทำไมต้อง 30: ถ้าวัดได้ 90% จาก 30 ใบ ช่วงความเชื่อมั่นยังกว้างราว ±10% พอใช้แยก engine ที่ห่างกันชัด ๆ ได้
  แต่ถ้าสองตัวห่างกันแค่ 2-3% ให้ถือว่า "เสมอกัน" แล้วตัดสินด้วยค่าใช้จ่าย/ความเป็นส่วนตัวแทน
- ให้หลากหลาย: โอนให้คน, PromptPay เบอร์/บัตร ปชช., สแกน QR ร้านค้า, จ่ายบิล, ยอดหลักหน่วยถึงหลักหมื่น,
  สลิปที่แอปบันทึกเอง vs screenshot, (ถ้ามี) dark mode

## ที่มาของสลิป & ความเป็นส่วนตัว
- ใช้สลิปของตัวเอง หรือของเพื่อนที่ **ยินยอมชัดเจน** (PDPA: ข้อมูลการเงิน + ชื่อบุคคลที่สาม)
- **ไม่ต้องปิดชื่อบนรูป** สำหรับชุดที่เก็บในเครื่อง ไม่งั้นจะวัดความแม่นของการอ่านชื่อไม่ได้
- **cloud OCR (Google Vision, Typhoon API) = ส่งรูปออกไปบุคคลที่สาม** ใช้ได้เฉพาะสลิปของตัวเอง
  ถ้าเพื่อนไม่ยินยอมให้ส่งออก ให้ใส่ `"cloud_ok": false` แล้ว runner จะข้ามใบนั้นสำหรับ cloud engine
- รูปที่จะใช้ใน README ต้องเบลอชื่อ/เลขบัญชี/QR แล้วเท่านั้น

## รูปแบบ label (`labels.jsonl` หนึ่งบรรทัดต่อหนึ่งสลิป)
```json
{"id": "kbank_001", "file": "kbank_001.jpg", "bank": "kbank", "amount": "150.00",
 "paid_at": "2025-11-03T12:34", "receiver_name": "นาย สมชาย ใจดี", "ref": "015307123456ABC12345",
 "kind": "transfer", "cloud_ok": true}
```
- `paid_at` เป็น **ค.ศ.** เสมอ (แปลงจาก พ.ศ. ตอน label) ตัดวินาทีทิ้ง
- `receiver_name` พิมพ์ **ตามที่ปรากฏบนสลิป** (ถ้าสลิปปิดบางส่วนเช่น `นาย สมชาย ใ***` ก็พิมพ์แบบนั้น)
- field ที่สลิปไม่มี ให้ใส่ `null` — จะไม่ถูกนับในตัวหารของ field นั้น
- `kind`: `transfer | promptpay | qr_merchant | bill` ไว้ดูว่า parser พังกับสลิปประเภทไหน
